# Quant Daily Knowledge - 2026-03-16

## Today at a glance
- 完成前端信息架构方案收敛：在 3 套方案中选定 **方案 A / 两级页面 + Tab 详情** 作为落地路径。
- 明确详情页目标：进入回测详情后必须可见资金曲线、逐笔明细/快照、策略参数与策略内容。
- 识别验收缺口：当前只能证明任务在跑和进度在更新，尚不能证明交易明细与结果明细已可靠落库。
- 新增问题清单：详情跳转失效、多个列表缺少 loading 态、任务在服务更新后疑似卡住（20.9%）。

## Changes
- **产品结构层面**：从“单页冗长滚动”切换到“列表页 + 详情页 + 子 Tab”的分层结构。
- **验收口径层面**：增加“落库可证据化”要求，避免仅凭进度条判断任务完成质量。
- **体验质量层面**：将 loading 态与详情跳转列为必修复项，而非后续优化项。

## Decisions
- **决策 1**：采用方案 A（两级页面 + Tab 详情）。
  - **原因**：实现复杂度可控，兼顾扩展性，能快速缓解当前滚动冗杂问题。
  - **备选**：Master-Detail 单屏、三级钻取；**未采用**，分别存在扩展受限或实现成本偏高问题。
- **决策 2**：把“交易/结果明细是否入库”作为下一阶段关键验收门槛。
  - **原因**：不落库将导致详情页数据不稳定、不可追溯，影响复盘与审计。
  - **备选**：先在线推导展示；**暂缓**，因一致性与性能风险更高。

## Risks / Issues
- **功能风险**：列表页“查看详情”无法跳转，直接阻断详情链路。
- **体验风险**：无 loading 态时误显示“无数据”，造成用户误判。
- **稳定性风险**：服务更新期间回测任务可能中断或卡进度（观察到 20.9% 卡住案例）。
- **实现风险**：若继续依赖在线推导而不落库，详情页一致性与排错难度都会升高。

## Next Actions (P0/P1)
- **P0**：修复列表页到详情页路由跳转，补自动化或最小回归检查。
- **P0**：为“新建回测任务状态/最近任务”“回测记录列表”补齐 loading、empty、error 三态。
- **P0**：验证服务更新对运行中任务的影响，明确是“可恢复暂停”还是“硬中断”，并修复卡死路径。
- **P1**：给详情页接口增加超时提示（>8s 显示“网络较慢，正在重试”）以提升可感知稳定性。
- **P1**：输出落库字段清单（回测任务、交易明细、权益曲线快照、参数快照）并与前端展示字段对齐。
